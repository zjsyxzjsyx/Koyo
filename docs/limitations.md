# 已知限制

目前已知的限制与取舍。返回 [README](../README.md)。

## 已知限制

- 同一输入在温度 0 下的评分仍可能相差一档，单次一致率会有波动，评分质量应按多次评分的平均值判断。
- 单道长答的分段评阅默认关闭：要点较多的长答在汇总步骤可能超出预算，需先实现分批汇总并通过人工样本检查后再启用。
- `verified` 只是配置声明，不会由程序自动推断；未做满额实测的窗口应保持 `false`。
- “停止”仍然只作用于等待中的提示，不打断正在进行的模型调用（V7 的决定；流式之后实现起来不难，列为 8.1 候选）。讲解等 JSON 阶段只显示字数，不边写边显示内容。
- 流式下的 usage 依赖端点在最后一个片段里返回；不返回时这次调用的 token 与花费记为空。
- 端点能力靠报错正文识别（9.0）：服务商措辞不同，个别拒绝可能认不出（照常报错，给出中文说明），或者把别的原因误当成某个字段不支持；只有正文点名字段时才记住，记错了可用 `zhiqiu check-model --reset` 清掉。
- 代码资料不带行号（9.0）：讲解按文件名和函数名引用，不保证行号准确；评分提示没有为代码资料单独调整，代码题的评分质量还没有用人工样本检查过。
- 授权卡片列出的上级目录在检查时会数文件（每级最多 2 万项或 3 秒），目录很大时弹卡会慢几秒。
- 学习计划（10.0）：
  - 定计划时模型只看到资料的路径和标题，拆分的粒度和顺序是否合理靠你在卡片上检查；程序只保证结构合法（数量、前置不成环、资料存在）。
  - 复习负荷只能预知 14 天（FSRS 每次只排下一次复习），更远的日子按“没有复习”排，靠每天的重排修正，所以远期日期会变。
  - 一起调整是每次一问一答的计划修改（模型在这一步不能读文件或联网），不是工具循环；对已经生效的计划，修改立刻生效（每次都存版本，可以撤销）。
  - 估时校准需要至少 3 次实际记录；实际用时从讲解与自测的消息时间推算，长时间离开不算，但边学边做别的事仍会算进去。
