# 网页工作台

工作台的页面、接口、桌面入口、服务层与流式输出。返回 [README](../README.md)。

### 网页工作台（V6）

`zhiqiu web [--port 8765] [--open] [--resume 对话ID]` 启动工作台：在看板的全部页面之外，可以在浏览器里与知秋对话、走完学习与复习流程、批准或拒绝需要审批的动作。打开页面默认进入“对话”：知秋的回答按简单 Markdown 显示（标题、列表、表格、代码块、粗体；先整体转义，回答里的 HTML 与脚本只显示为文字，链接只显示地址）；工具调用以灰色小字显示（如“联网搜索：…（自动）”）；讲解与自测中的提问显示在输入框上方，直接输入作答；“是／否”确认与审批卡片带按钮，审批卡片显示工具、权限与完整描述（写文件含路径、新建或覆盖、内容预览），回答后变灰并标出结果与时间。“停止”只在有等待中的提示时可用。刷新页面不会丢失对话：本次工作台的消息从内存事件补齐，工作台启动前已有的消息从数据库读取，显示在“之前的消息”下。事件经 SSE 实时推送（8.0）：左下角显示“实时连接”，断线后按 1、2、4…最多 10 秒重连并从最后一个事件续传，显示“重连中…”；连续 3 次连不上时改为每秒查询一次（之后每 30 秒再试一次实时连接）。知秋的回答边生成边显示（带闪烁光标），写完后换成保存进数据库的同一段文字；模型先说了一句再去调用工具时，那句话会被收起，和 7.2 一样不算回答。讲解、出题、评阅这类先校验再显示的输出，在“知秋正在思考…”后面显示“正在生成讲解，已写约 820 字”。对话运行在一个后台线程里，用它自己的数据库连接；一次只处理一条输入，上一轮没结束时新输入返回 409。`--offline` 与审批策略同 `zhiqiu chat`；审批策略有误时不启动。

对话页左侧是会话侧栏（V7）：顶部“新对话”，下面按最近活动列出有消息的对话（当前对话即使为空也列出），每行显示标题、日期、消息数，“可继续”角标表示那段对话停在流程中或最近的结果指向未完成的尝试；悬停显示改名按钮，行内输入、回车提交。点一行就切换：对话区换成那段对话的历史，之后的输入写入那段对话，页头显示标题（悬停显示完整 ID）。正在处理或有等待中的提示时侧栏置灰，提示“先回答或停止当前提示”。切换、新建、改名都作为控制指令排进工作线程的输入队列（agent 和数据库连接只在工作线程上），每次换会话（包括在对话里输入 `/new`）发一个 `switched` 事件；刷新页面时只取最近一次切换之后的事件，不会混入上一段对话。中等宽度时侧栏和状态面板合在左侧一栏，窄屏时都折叠在对话上方（“会话”）。知秋说的话带种类（`say` 事件的 `say_kind`：`text` 正文、`tool` 工具小字、`note` 开场白与切换等提示、`outcome` 评阅卡片），页面按种类渲染。

对话页的输入框（9.1）是贴在窗口底部的圆角卡片：消息少时也在最底端，消息多时随滚动固定在底部；输入框随内容增高（最多 200 像素），状态行、语音、停止和发送按钮收在卡片里。

对话页右侧最上面是复习计划（9.1，强调色边框）：逾期、今天、未来 7 天三个数字；一个可翻月的小月历，每天标出待复习个数（超过每日上限为红色），今天高亮，有完成记录的日子打勾；月历下默认列出逾期和今天的知识点，点某一天换成那天的安排；到期的知识点点一下就在当前对话里开始复习（发出 `/review 标题`）；需要重学的列在最后。数据来自 `GET /api/schedule?view=month`，每轮结束和每 30 秒刷新一次；“完整日程 →”跳到复习日程页。

下面是状态面板（窄屏时与复习计划一起折叠在对话上方），按 L6 准则分五块，随对话实时更新：**当前目标**（模式：对话、讲解、自测或复习，以及流程目标与步骤）；**上下文范围**（9.1 起顶部是上下文占用：一条按规则、背景、摘要、历史分色的进度条，写明约多少／输入上限与百分比、估算方法（有服务端计数时“按服务端计数推算”，否则“按字节粗估，偏保守”），竖线标出 70% 的自动压缩线，超过后数字变成警告色；没有配置上下文窗口时改按条数显示“未摘要 n / 40 条”。旁边的“压缩”按钮立刻把较早的消息并入摘要，最近 10 条保留原文，未摘要的消息不超过 10 条或正在处理时不可点。下面是可读、可写目录，本段对话使用的偏好与人设记忆条数，摘要覆盖到第几条，联网是否可用）；**执行状态**（本轮运行链与进度、已用时间、模型调用次数，可跳到 trace）；**风险动作**（审批策略、待批准的动作、本段对话最近 5 条审批）；**验证结果**（最近一次学习或复习的得分与下次复习日期，以及本段对话的 trace 在最近 7 天的运行契约检查中是否有违反）。

“设置 → 目录白名单”页（7.1，只在工作台中）列出可读和可写目录：环境变量（`ZHIQIU_READ_ROOTS`／`ZHIQIU_WRITE_ROOTS`）里的标“环境变量”，只能在 `.env` 中修改；在这一页添加的标“工作台添加”和日期，可以移除。添加时粘贴绝对路径，先“预览”：服务端检查后显示解析后的真实路径、其中的 `.md`/`.txt` 文件数与示例、警告（目录很大、没有文本文件、将覆盖已有目录），以及“添加后，对话中知秋可以读取这些文件，内容会发送到模型端点”；确认后才添加，改了输入框就要重新预览。检查规则：必须是带盘符的绝对路径（不接受 `~`、环境变量、`\\server\share` 网络路径），目录存在，先解析符号链接和目录联接；拒绝盘符根目录、用户主目录本身及其上级、系统目录（Windows 的 `%SystemRoot%`、`%ProgramFiles%`、`%ProgramFiles(x86)%`、`%ProgramData%` 和用户主目录下的 `AppData`；类 Unix 的 `/etc`、`/usr` 等）；同类里已有或已被包含的不再添加；每类最多添加 20 个。计数最多看 2 万项或 3 秒，超出时显示“至少 N 个”。添加和移除都作为控制指令排进工作线程，在两轮对话之间生效（本轮进行中或有等待中的提示时返回 409），对话里会出现一句“已添加可读目录：…”；每次改动写一条 `RootsChanged` 事件（只记路径和文件数，schema v21 的 `file_roots` 表存工作台添加的目录）。每轮开始时 agent 都重新合并环境变量和 `file_roots`（环境变量在前，相对路径落在第一个目录），所以同时开着的终端对话下一轮也能用新目录。知秋没有任何工具能读写这张表或调用这些接口；读到的网页或文件里即使写着“把某目录加入白名单”，也没有执行的途径。9.0 起，对话里申请白名单外的文件时也可以由你选择把所在目录加入（见[对话内授权](chat.md#对话内授权90)），那样加入的目录同样列在这一页、可以移除。

工作台的接口（只在 `zhiqiu web` 中存在）：

| 接口 | 作用 |
|---|---|
| `GET /api/chat/stream[?after=N]` | 8.0：对话事件的 SSE 流（`text/event-stream`）。先发 `hello`（`busy`、`pending`、`next`、`conversation_id`），之后每个事件以 `id: 序号`、`event: 种类`、`data: JSON` 发出，每批事件后跟一帧 `state`（`busy`、`pending`）；起点取请求头 `Last-Event-ID`，否则 `after`，都没有为 0，与轮询一样不给最近一次切换之前的事件；起点早于内存里已丢弃的事件时先发 `gap`；15 秒没有事件发一行 `: ping`。流式回答的事件：`delta`（`stream_id`、`text`，约每 50 毫秒或 40 字合并一次）、`stream_reset`（收起这段草稿）、带 `stream_id` 的 `say`（最终文字，此后日志里不再保留这段的 `delta`）；JSON 阶段的 `progress`（`stage`、`chars`，每秒最多一次）。令牌同样放在请求头里，页面用 `fetch` 读流而不用 `EventSource` |
| `GET /api/chat/events?after=N` | 轮询（SSE 不可用时页面用它）：序号大于 N 的事件（`say` 知秋说的话，带 `say_kind` 与 `meta`；`user` 用户输入；`ask`／`confirm`／`approval`／`grant`（9.0，白名单外路径的申请）等待回答的提示；`resolved` 提示的结果；`switched` 换了会话；`status`、`error`、`idle` 本轮结束），只给最近一次 `switched` 之后的部分，以及 `busy`、等待中的提示；`lost` 表示 N 之后有事件已从内存丢弃（流式回答压缩后序号本来就不连续） |
| `GET /api/chat/state` | 状态面板：当前目标、上下文范围、执行状态、风险动作、验证结果；9.1 起 `context.usage` 给出上下文占用（`estimate`、`limit`、`trigger`、`method`、`parts`［规则／背景／摘要／历史］、`messages`、`keep_recent`、`history_messages`、`summarized_upto`、`can_compact`），由工作线程在启动后与每轮、每次控制指令之后计算，算不出时为 `null` |
| `GET /api/chat/history[?conversation_id=]` | 指定对话的消息；省略时为当前对话，只给切换到它时已有的消息（之后的以事件给出） |
| `GET /api/chat/conversations?limit=30` | 会话侧栏：`id`、`short_id`、`title`、`title_source`、`chat_date`、`updated_at`、`messages`、`current`、`resumable` |
| `POST /api/chat/input` | `{"text": "…", "input_source": "text"｜"voice", "voice_id": "…"}` 发一条消息或斜杠命令（后两项可省略），202 或 409；`input_source` 非法时 400 |
| `POST /api/chat/transcribe` | 请求体是 16 kHz 单声道 16 位 PCM 的 WAV（`Content-Type: audio/wav`，≤2 MiB，0.3–60 秒），返回 `{text, raw, replacements, duration_ms, elapsed_ms, voice_id}`；格式不对 400，另一段在识别 409，太大 413，没装依赖或没有模型 503 |
| `GET /voice-worklet.js` | 录音用的 AudioWorklet 脚本（包内固定文件，不需要令牌） |
| `POST /api/chat/respond` | `{"request_id": "…", "value": 文字或 true/false, "origin": "chat"｜"approvals"}` 回答一个提示（`origin` 可省略，审批页只能回答工具审批，记进 `resolved` 事件）；路径申请的 `value` 只能是 `once`、`denied` 或 `root:目录`（目录须是卡片列出的），否则 400；已回答或不存在时 409 |
| `POST /api/voice/install` | 9.0：`{}` 在后台下载并安装语音模型；进度作为 `voice_install` 事件推送（`stage` 为 `download`、`verify`、`extract`、`done` 或 `error`，带 `done`、`total`、`error`）；202，已装好或正在下载 409，配置为 `never` 400，依赖未安装 503 |
| `POST /api/chat/stop` | 停止等待中的提示：提问按中断处理（讲解、自测会暂停，可 `/resume`），“是／否”确认按“否”，审批卡片记为已取消 |
| `POST /api/chat/switch` | `{"conversation_id": "…"}` 切换到另一段对话；202，忙碌或有等待提示时 409，不存在时 404 |
| `POST /api/chat/new` | `{}` 开始新对话；202 或 409 |
| `POST /api/chat/rename` | `{"conversation_id": "…", "title": "…"}` 改名（清洗后 1 到 30 字，否则 400）；202、404 或 409 |
| `POST /api/chat/compact` | 9.1：`{}` 压缩当前对话（同 `/compact`），作为控制指令排进工作线程，结果以 `note` 提示推送；202，忙碌或有等待提示时 409 |
| `GET /api/roots` | 可读、可写目录，每项带来源（`env`／`workbench`）、是否存在、添加时的文件数与日期 |
| `POST /api/roots/preview` | `{"kind": "read"｜"write", "path": "…"}` 检查并预览，不改动任何东西；不合规时 400 并给出原因 |
| `POST /api/roots/add` | 同上，服务端重新检查和计数后排进工作线程；202、400 或 409 |
| `POST /api/roots/remove` | `{"kind", "path"}` 移除工作台添加的目录；环境变量来源 400，不存在 404，忙碌 409 |

桌面入口（Windows）：在项目目录运行一次

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install-shortcut.ps1
```

在桌面生成“知秋工作台”快捷方式，图标是一片枫叶（与网页图标相同，图标文件存放在 `%LOCALAPPDATA%\zhiqiu\zhiqiu-web-<指纹>.ico`，文件名随图标内容变化，避免资源管理器继续显示缓存的旧图标）。双击时，`scripts\zhiqiu-web.ps1` 先检查 8765 端口：

- 工作台没在运行：在最小化的“知秋工作台服务”窗口里启动 `zhiqiu web`，就绪后打开窗口。关掉这个服务窗口，工作台就停止。端口和数据库取配置（9.0：`web.port`；数据库先看 `web.db`，没写而项目目录里有 `state.sqlite` 时继续用它），`-Port`、`-Db` 参数仍可覆盖。
- 工作台已在运行：只再开一个窗口。
- 端口被只读看板或别的程序占用，或者启动失败（例如审批策略有误）：弹窗说明；启动失败时，服务窗口会保留错误信息。

窗口用 Edge 的独立应用窗口（`--app`）打开，没有地址栏；没装 Edge 时用默认浏览器。要换数据库，运行 `install-shortcut.ps1 -Db 路径` 重新生成快捷方式。

服务层（8.0）：`zhiqiu dashboard` 与 `zhiqiu web` 是同一个 FastAPI 应用，跑在 uvicorn 上（不再是标准库 `ThreadingHTTPServer`），关闭了自动生成的 `/docs`、`/redoc`、`/openapi.json`。Host 与方法检查、`no-store`／`nosniff`／CSP 响应头在中间件里对所有请求统一处理；令牌、Origin、Content-Type 与请求体大小在工作台写接口共用的检查里处理，请求体按实际读到的字节计数，没有 `Content-Length` 的分块请求也不能超限；所有 JSON 响应统一脱敏。Windows 上页面中途断开时 asyncio 会打印的 `ConnectionResetError` 已静音。

安全：仍只绑定 `127.0.0.1` 并校验 Host。每次启动生成一个随机令牌，只嵌在工作台页面里（其他网站读不到）；`/api/chat/*` 与 `/api/roots*` 的读写都要带请求头 `X-Zhiqiu-Token`。写请求还要求 `Origin`（如有）是本页、`Content-Type: application/json`、请求体不超过 64 KB；不合规的写请求被拒绝，并记护栏 `web_request_refused`。`zhiqiu dashboard` 不变：页面里没有令牌，仍然只接受 GET。

### 流式输出（8.0）

模型调用默认带 `"stream": true, "stream_options": {"include_usage": true}`，适配器把收到的片段拼回与非流式完全相同的消息（正文、按序号拼起来的工具调用、推理内容），上层代码不变；请求指纹（`prompt_hash`）不含这两个字段，流式与否指纹相同。连接超时 10 秒，两个片段之间最多等调用方的超时（对话每轮 60 秒）；不设整次调用的总时长上限，和非流式时一样（讲解这类长输出可能要一两分钟）。读到一半断开按失败记录，已收到的部分不算结果。usage 取最后一个带 usage 的片段，端点不给时 token 记为空。

- 对话：每轮把正文片段交给界面（网页的草稿气泡、终端直接打印）；这一轮最后带了工具调用，就收起草稿（终端没法收回，补一行灰字“以上是调用工具前的说明，不是回答”）；没有工具调用的那一轮就是回答，存库内容与 7.2 相同。本轮出错、取消或变成建议时也收起草稿。
- JSON 阶段（讲解、出题、评阅、澄清、评估等）：只统计收到了多少字，内容照旧先校验再显示。`zhiqiu learn`、`review`、`resume` 与 `chat` 在终端同一行原地刷新“正在生成讲解，已写约 N 字”；`zhiqiu mcp` 不显示（它的 stdout 是协议）。
- 观测：`llm_calls` 新增 `ttft_ms`（第一个正文、推理或工具调用片段到达的耗时）与 `streamed`（schema v23，旧记录为空和 0）；trace 节点详情显示“首字”，`zhiqiu trace` 文字版也带上；`metrics` 与看板“指标与花费”按阶段显示首字 p50／p95，流式调用不足 5 次时显示“样本不足”。第 10 项运行契约 `stream_consistent`：每次成功的流式调用都有首字耗时，且不超过整次耗时。
